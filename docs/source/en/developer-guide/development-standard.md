# Development conventions

## Naming

| Element | Convention | Example |
| --- | --- | --- |
| Packages and file names | snake_case | `signal_bus.py` |
| Classes | PascalCase | `MainWindow` |
| Functions and variables | camelCase, consistent with Qt | `switchToAlbumInterface` |

Match nearby code when extending existing classes.

## Repository layout

- `app/common/`: shared functions, configuration, library code, data access and other application services.
- `app/components/`: reusable widgets, including buttons, menus, dialogs and playback components.
- `app/View/`: main window and individual application screens.
- `app/resource/`: icons, style sheets, translations and Qt resources.
- `app/config/`: runtime settings such as `config.json`, where generated by the application.
- `app/cache/`: runtime artwork, database and log data, where generated by the application.
- `tests/`: test cases and development checks. Rerun the relevant tests after modifying code; GUI tests may require a display.
- `docs/`: user and developer documentation, including Sphinx sources.

Maintain both language editions when changing public documentation. Use the current dependency and development configuration described in [Development setup](quick-start.md). See the [Sphinx documentation](https://www.sphinx-doc.org/) for background on the existing documentation system.
